Crie um sistema web completo chamado “Ponto Digital DIGEP” para automatizar o recebimento, identificação, conferência, arquivamento, consulta e envio de folhas de ponto dos servidores e professores da Universidade do Distrito Federal – UnDF.

IMPORTANTE:
- Não crie apenas um protótipo visual.
- Implemente um MVP funcional de ponta a ponta.
- Antes de programar, analise os arquivos fornecidos no projeto:
  1. Projeto - Folhas de ponto da DIGEP.pdf
  2. Modelo de folha de ponto - Exemplo.docx
  3. Planilha de professores - exemplo.xlsx
  4. Input - Folhas de ponto escaneadas - Exemplot.pdf
  5. FolhaPonto-main.zip
- Aproveite o que for útil do código existente, mas corrija os erros e reorganize a estrutura.
- Não exponha documentos, credenciais ou dados pessoais em páginas públicas.

OBJETIVO DO SISTEMA

A DIGEP recebe mensalmente centenas de folhas de ponto digitalizadas. O sistema deverá:

1. importar a planilha de servidores;
2. receber um PDF com uma ou várias folhas de ponto;
3. separar automaticamente cada página;
4. aplicar tratamento de imagem;
5. executar OCR;
6. identificar matrícula, nome e competência;
7. relacionar a folha ao servidor cadastrado;
8. permitir conferência humana;
9. arquivar a folha;
10. permitir pesquisa, visualização e download;
11. identificar servidores que acumulam cargo;
12. enviar suas folhas ao e-mail pessoal cadastrado;
13. registrar todo o processamento e o resultado dos envios.

TECNOLOGIAS

Utilize:

- Frontend: React + TypeScript + Vite
- Interface: Tailwind CSS + componentes acessíveis
- Backend: Python + FastAPI
- Banco de dados: PostgreSQL
- ORM: SQLAlchemy
- Validação: Pydantic
- OCR: PaddleOCR
- Imagens: OpenCV
- PDFs: PyMuPDF
- Autenticação: JWT com senhas criptografadas
- Testes backend: Pytest
- Testes frontend: Vitest
- Docker Compose para aplicação e banco

Se alguma tecnologia não funcionar no ambiente do Replit, escolha uma alternativa compatível, explique a mudança no README e mantenha todas as funcionalidades.

- permitir baixar um relatório dos erros;

3. UPLOAD EM LOTE

Aceitar:

- vários PDFs;
- PNG;
- JPG e JPEG.

O sistema deve:

- validar formato e tamanho;
- impedir arquivos maliciosos;
- gerar hash SHA-256;
- detectar duplicidade;
- manter o arquivo original;
- transformar cada página em uma folha individual;
- mostrar o progresso do processamento.

4. OCR E EXTRAÇÃO

Antes do OCR:

- corrigir orientação;
- converter para escala de cinza;
- melhorar contraste;
- reduzir ruído;
- aplicar binarização;
- corrigir inclinação quando necessário.

Extrair prioritariamente:

- matrícula;
- nome do servidor;
- competência no formato mês/ano;
- cargo;
- carga horária;
- unidade de exercício.

Utilizar expressões regulares e a posição dos campos no formulário da UnDF.

A matrícula é o identificador principal. O nome deve ser utilizado como validação secundária.

Para cada campo, guardar:

- valor extraído;
- confiança do OCR;
- valor corrigido, se houver;
- usuário que corrigiu;
- data da correção.

5. REGRAS DE CONFIANÇA

- Acima de 90% e matrícula encontrada: classificar como “Reconhecido”.
- Entre 70% e 89%: classificar como “Revisão necessária”.
- Abaixo de 70%: classificar como “Baixa confiança”.
- Matrícula não encontrada: “Servidor não identificado”.
- Matrícula e nome incompatíveis: “Possível divergência”.
- Nunca descartar uma folha por erro de OCR.

6. CONFERÊNCIA HUMANA

Criar uma tela dividida:

- lado esquerdo: visualização da folha;
- lado direito: dados reconhecidos.

Permitir:

- selecionar servidor;
- corrigir matrícula;
- corrigir nome;
- corrigir competência;
- consultar confiança;
- confirmar associação;
- rejeitar processamento;
- adicionar observação;
- encaminhar para pendência.

Somente depois da confirmação a folha poderá ser considerada arquivada.
